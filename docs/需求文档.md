# 项目需求文档 - V1.9

## 0.0 基础要求
本题目开发一个基于ROS小车教学内容的在线教学网站，实现教学资源的数字化、结构化与可持续更新。教学内容展示模块支持章节化内容管理（章节、子章节层级结构），内容包括文字、图片、代码段、外部视频链接（如B站教学视频）等。内容管理与动态更新支持模块管理员（教师）通过后台界面添加、修改或删除教学章节与内容，支持Markdown或富文本编辑，方便快速更新教材内容。
网站结构采用前后端分离架构，前端设计界面简洁直观，支持自适应显示（电脑与移动端），章节目录导航清晰，为学生提供一个集理论学习、实验指导、视频演示、持续更新于一体的智能无人系统教学平台。

## 1.0 项目愿景

打造一个一体化的多教材文档解决方案。该方案需提供一个专业、现代化的前端阅读体验，并配备一个**安全、可协作、对非技术人员极致友好**的后台管理系统，该系统需具备版本管理、细粒度权限控制和集中的媒体管理能力。

## 2.0 核心需求

### 2.1 前端表现（阅读体验）

1.  **三栏式布局**：采用“**左侧教材目录 + 中间内容区 + 右侧页内目录**”的布局。
2.  **顶部教材导航**：通过顶部常驻导航栏在不同“教材”间快速切换。
3.  **左侧教材目录**：支持**最多三层**的嵌套（**章、节、小节**），并可折叠。
4.  **右侧页内目录 (On-page TOC)**：根据当前页面内的标题**自动生成**，提供页内快速跳转。
5.  **内容富媒体化**：支持 Markdown、图片嵌入和链接跳转。
6.  **清晰的视觉风格**：整体外观简洁、专业，可参考 Koishi 文档网站的风格。
7.  **全文搜索**：前端需提供搜索功能，允许读者对全部或单个教材内容进行关键词搜索。具体实现方案（如客户端搜索或服务端搜索）待技术设计阶段确定。
8.  **响应式设计**：
    *   **功能描述**：网站必须采用响应式设计，确保在桌面电脑、平板和手机等不同尺寸的设备上都能提供良好、一致的阅读和交互体验。
    *   **实现要求**：在移动端，左右侧边栏等导航元素应自动折叠为图标或抽屉式菜单，以保证内容区域的可读性。

### 2.2 后端体验（内容管理）

1.  **面向非技术人员**：整个管理流程必须对内容管理者完全友好，屏蔽所有技术细节。
2.  **分教材管理**：后台应提供“教材列表”，允许管理者选择特定教材进行管理。
3.  **结构化内容管理**：通过**树状目录**对“章 -> 节 -> 小节”三级结构进行可视化操作。
4.  **灵活的页面映射**：允许目录项被定义为“**纯分类**”或“**内容页面**”。
5.  **Markdown 编辑**：提供 Markdown 编辑器，支持分屏预览（左边源码、右边渲染），并配备常用格式工具栏按钮（加粗、标题、列表、代码块、链接、图片等），方便教师快速编写内容。
6.  **自动化发布**：通过后台“发布”按钮触发自动化的网站构建和部署流程。
7.  **内容版本管理**：为每个页面提供版本历史记录、差异对比和一键恢复功能。
8.  **用户角色与权限管理 (RBAC - V2)**：
    *   **功能描述**：系统需支持基于角色的、可精细化配置的权限控制体系。
    *   **角色层级与权限继承**：
        *   **超级管理员 (Super Admin)**：系统的最高所有者。其权限为所有其他角色权限的**超集**，并独占系统级的管理权限（如：创建/删除教材库、管理所有用户与角色）。这意味着超管可以执行系统内任何管理员或编辑能够执行的操作（例如，直接在任何教材库中添加/管理编辑）。
        *   **管理员**：由超管指定，负责一个或多个完整的“教材库”。
        *   **编辑**：由“管理员”或“超级管理员”在其负责的教材库中添加，并分配具体操作权限。
    *   **权限分配模型**：
        *   **超管 -> 管理员**：按“教材库”进行授权。
        *   **管理员 -> 编辑**：在其负责的库内，按“具体操作”（如：编辑页面、创建/删除页面、修改目录结构等）进行独立的、可组合的授权。管理员不能授予用户管理权限。
    *   **目的**：实现灵活、安全、分层级的团队协作模式。

### 2.3 系统特性（技术与运维）

1.  **高性能与低成本**：最终生成的网站访问速度要快，服务器和带宽成本要可控。
2.  **安全性**：能抵御简单的流量攻击，并确保资源安全。
3.  **可部署与可控**：整个系统支持私有化部署。
